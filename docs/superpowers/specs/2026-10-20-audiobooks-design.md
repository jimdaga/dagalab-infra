# Audiobooks on dagalab: design

Date: 2026-10-20

## Intent

What the user asked for:

- Audiobookshelf as the audiobook + podcast server, reachable from the phone apps at home and away.
- The user's Audible library backed up automatically as DRM-free files (Libation, a daily CronJob).
- Audiobooks requested and downloaded through the *arr stack (Bookshelf, wired to Prowlarr + qBittorrent).
- Audiobooks only: no ebooks. Podcasts come from RSS feeds via Audiobookshelf itself, never torrents.

Assumptions confirmed with the user:

- Public at an unadvertised name on the shared gateway (like Jellyfin and Seerr), plus a LAN name.
- Bookshelf (the Hardcover-metadata image) over Chaptarr (closed source, licence questions).
- Seerr is not involved (it can't request books); requests are made in Bookshelf's UI.
- Indexers: IPTorrents and wigornot have an audiobook category (3030); TorrentLeech only general Audio (3000). All
  three are active.

Success: a book requested in Bookshelf and a Libation-backed-up Audible book both play in the Audiobookshelf phone
app over cellular, a podcast episode plays, and listening progress syncs between two devices.

## Components

All three are app-template 5.2.1 Applications in namespace `media`, sync wave 0, images pinned (Renovate bumps them).
Each runs as DSM user `media` (1029:100); SQLite/config always on Longhorn, never NFS.

| App | Image | What it does |
|---|---|---|
| `audiobookshelf` | `ghcr.io/advplyr/audiobookshelf:2.37.1` | Player/server: Audiobooks + Podcasts libraries, per-user progress, phone apps |
| `bookshelf` | `ghcr.io/pennydreadful/bookshelf:hardcover-v0.4.21.182` | Readarr fork: search, grab, import audiobooks |
| `libation` | `rmcrackan/libation:14.2.2` | Daily CronJob: download + decrypt new Audible purchases |

### Media share layout (inside `/data` = `/volume2/video`)

New top-level folders (lowercase-hyphen, owned by 1029:100, created once by hand as the `media` user, since root is
squashed on NFS and kubelet can't create subPath directories):

| Folder | Written by | Read by |
|---|---|---|
| `audiobooks/` | Bookshelf (root folder; `Author/Book/` files, hardlinked from downloads) | Audiobookshelf |
| `audible/` | Libation (`Author/Book/` `.m4b`) | Audiobookshelf |
| `podcasts/` | Audiobookshelf (RSS downloads) | Audiobookshelf |
| `downloads/audiobooks/` | qBittorrent (category `audiobooks`) | Bookshelf (import) |

`audible/` is separate from `audiobooks/` so Bookshelf never sees Audible backups as unmapped books to manage.
`personal/`, `iMovie/`, `youtube/` are untouched (never mounted by these apps).

### Audiobookshelf

- Service port 80 → container port 13378 (`PORT=13378`: non-root can't bind 80).
- Mounts (subPath of `media-data`, so it can't touch `movies/` or `tv/`):
  - `/audiobooks` ← `audiobooks/`, **read-only**
  - `/audible` ← `audible/`, **read-only**
  - `/podcasts` ← `podcasts/`, read-write (episode downloads)
  - `/config` (Longhorn 2Gi, SQLite DB), `/metadata` (Longhorn 10Gi: covers, cache, backups)
- Libraries: "Audiobooks" (folders `/audiobooks` + `/audible`), "Podcasts" (`/podcasts`). The folder watcher doesn't
  see NFS changes, so each library has a scheduled scan, hourly. No web uploads (books arrive via Bookshelf/Libation).
- Strategy Recreate; probe `GET /healthcheck`.
- Setup script `scripts/audiobookshelf-setup.{sh,py}` (idempotent, same shape as `seerr-setup`): creates the root
  user `jim` (generated password → Vault `secret/audiobookshelf` `root-password`), the two libraries with their scan
  schedule, and an API key for Homepage (`secret/audiobookshelf` `homepage-key`). Family accounts are created by the
  user in the UI (long random passwords; no upload/delete rights).

### Bookshelf

- Like Sonarr: linuxserver-style base (`PUID=1029`, `PGID=100`), port 8787, probe `/ping`, `/config` on Longhorn 5Gi,
  whole `media-data` at `/data` (needed so imports hardlink from `downloads/`).
- `READARR__AUTH__METHOD: External` (LAN only, auth outside the app, same reasoning as Sonarr; must switch to Forms
  before any public exposure). API key: Vault `secret/bookshelf` `api-key` (generated by `vault-bootstrap.sh`) →
  ExternalSecret `bookshelf` → `READARR__AUTH__APIKEY`.
- LAN only: `https://bookshelf.lab.internal`.
- Wiring, added to `scripts/arr-wire.py` (idempotent):
  - qBittorrent download client, category `audiobooks` (→ `/data/downloads/audiobooks`).
  - Root folder `/data/audiobooks`; hardlinks on; rename on.
  - Prowlarr application "Readarr" → Bookshelf, sync categories 3030 (Audio/Audiobook) and 3000 (Audio, for
    TorrentLeech).
  - Quality profile "Audiobook": M4B preferred over MP3; FLAC/unknown not allowed. Metadata profile: audiobook format.
    (Recyclarr doesn't support Readarr-family apps, so the script owns these, unlike Sonarr/Radarr.)
- Renovate: packageRule with `versioning: regex:^hardcover-v(?<major>\d+)\.(?<minor>\d+)\.(?<patch>\d+)(\.(?<build>\d+))?$`
  so the `hardcover-` prefix is understood (like the Plex rule).

### Libation

- app-template `cronjob` controller: schedule `30 3 * * *` (America/New_York), `concurrencyPolicy: Forbid`, no
  retries within a night (`backoffLimit: 0`); a failed night shows up as a failed Job (alert in follow-ups).
- Runs as 1029:100. `SLEEP_TIME` unset (= run once and exit).
- Mounts: `/config` ← Longhorn PVC `libation-config` 1Gi (AccountsSettings.json with the Audible tokens Libation
  refreshes itself, its SQLite DB, Settings.json); `/data` ← `audible/` (subPath).
- Settings: seeded once if missing (init container, like Home Assistant's seed): single `.m4b` per book, decrypted,
  folder template `<author>/<title short>` (what Audiobookshelf expects).
- Audible sign-in (one-time, manual; like the Plex claim): a temporary pod with the same PVC runs
  `LibationCli login-external --libationFiles /config`; the user opens the printed URL, signs in, pastes the final
  URL back. Tokens never go to git or Vault (Libation rewrites them on refresh, a static copy would go stale).
  Re-run only after losing the PVC or if Audible revokes the tokens.

## Networking

- Public: `https://books.dagaflix.com` → `audiobookshelf:80` on the shared gateway (`helm/charts/shared-gateway`
  routes). Wildcard DNS + wildcard cert already cover it. The phone apps use this name everywhere (the UCG hairpins
  the WAN IP at home, verified with `popcorn` and `requests`).
- LAN: `https://books.lab.internal` (Audiobookshelf) and `https://bookshelf.lab.internal` (Bookshelf) in
  `helm/charts/lan-gateway/values.yaml`; UniFi DNS records → .201 (user adds); Homepage tiles with widgets
  (Audiobookshelf: library stats via `homepage-key`; Bookshelf: Readarr widget via the API key).
- Must work through Envoy: long audio streams (range requests), the socket.io websocket that syncs progress.

## Security

- `books.dagaflix.com` is the third public route. Audiobookshelf's own accounts protect it: long random passwords,
  non-admin family accounts. Image updates are merged promptly (internet-facing), as with Plex.
- Bookshelf stays LAN-only with `External` auth; never routed on the shared gateway.
- Audiobookshelf can write only to `podcasts/`; Libation only to `audible/`; Bookshelf to the share like Sonarr.

## Testing / done when

1. Argo CD: `audiobookshelf`, `bookshelf` Synced/Healthy; `libation` CronJob present; processes run as uid 1029.
2. Audiobookshelf can't write `/audiobooks` or `/audible`; can write `/podcasts`. Libation can't see `movies/`.
3. `https://books.dagaflix.com` and `https://books.lab.internal` load; unauthenticated API calls get 401; other
   made-up `dagaflix.com` names still get the placeholder.
4. Bookshelf: Prowlarr shows it as an app with the three indexers synced; a test audiobook search returns results;
   a grabbed book lands in `downloads/audiobooks`, imports to `audiobooks/` as a hardlink (link count 2).
5. Libation: after the sign-in, a manually triggered Job (`kubectl create job --from=cronjob/libation`) downloads at
   least one Audible book into `audible/Author/Title/*.m4b`.
6. Audiobookshelf shows both books within an hour (scheduled scan) or immediately after a manual scan.
7. Phone on cellular: plays a book (seek works mid-file) and a podcast episode; progress shows on a second device.
8. Homepage tiles render with widgets (Playwright screenshot check).

## Changes during implementation (2026-10-20)

These supersede the sections above where they differ.

1. **Storage.** subPath mounts can't work on `media-data` (root is squashed to guest and DSM denies guest, so kubelet
   can't prepare subdirectories) and the NAS refuses subdirectory mounts. The user created two DSM shares instead:
   `audiobooks` (`/volume2/audiobooks`: `library/` = Bookshelf root, `audible/` = Libation) and `podcasts`
   (`/volume2/podcasts`), each its own PV/PVC in `helm/charts/media-storage`. Audiobookshelf mounts only these
   (`/audiobooks` read-only, `/podcasts` read-write), Libation only `audiobooks`. Bookshelf mounts both `media-data`
   (downloads) and `audiobooks`; imports **copy** (hardlinks can't cross shares).
2. **Seeding.** Audiobook torrents are deleted (torrent + downloaded files) by an hourly `seed-cleanup` CronJob in the
   Bookshelf app once ratio ≥ 3 **and** 14 days seeded **and** imported (qBittorrent's share limits are OR-only).
   Movies/TV keep seeding forever.
3. **Bookshelf format.** Audiobooks-only comes from the quality profile alone; the default metadata profile is used.
4. **Libation settings** come from a git ConfigMap (the image copies `Settings.json` in and never writes it back);
   the CLI also needs a copy on the PVC for the one-time sign-in. Tokens are encrypted with
   `/config/libation-master.key` on the same PVC.
5. **Homepage** reads Audiobookshelf through a dedicated read-only `homepage` user's API key.
6. **Indexers.** wigornot isn't synced to Bookshelf yet: Bookshelf's add-test needs recent results in 3000/3030.
